# aidata L1–L5 清理与整理 Plan v4（2026-07-27，经 codex 三轮核对修订）

> **For agentic workers:** 逐项 TDD/小步提交。每项改动后 `python3.13 -m pytest tests/ -q -m "not integration"` 不得新增失败。**基线（已核实）：`pytest` 全量 376 collected；`-m "not integration"` = 7 deselected、369 selected，其中 2 个 pre-existing 失败：`test_digest_golden::test_build_digest_matches_golden` 与 `test_work_by_project_card::test_container_has_metric_card_per_project`。**
> **失败真因（codex 二轮纠正，已核实）**：不是"措辞漂移"。`test_digest_golden` 的 fixture **只 patch 了 `fetch_ado_pr_trends`，漏 patch GitHub/combined PR fetcher（`fetch_combined_pr_trends`）**，导致 golden 的"开PR"行与真实 PR 数据不符；`test_work_by_project_card` 是 `unit == 'turns'` vs `'次交互'` 的单位断言与实现不一致。两者都是**测试侧 fixture/断言未跟上实现**，非本清理引入。
> **门禁定案**：本清理**先不碰这两个 pre-existing 失败的成因代码**；验收口径 = "**同样这 2 个失败、0 个新增失败**"。⚠️ **T10 lint 清理有一个陷阱**：任何触及 PR-fetcher / digest PR 渲染路径的改动，可能把 `test_digest_golden` 从"断言失败"恶化成"fixture error/collection error"——所以 T10 **严格只删 F401 unused-import，且排除任何涉及 fetcher/PR/digest 数据流的符号**；改动前后都跑该测试确认失败模式不变（仍是断言失败，不是 error）。`ruff check` 对改动文件必须干净。

## 背景与修订说明

本会话在 aidata 快速迭代加入 **7 个全新 L1 源**（`hermes_tools, multica_comment, news, aidash_events, local_git, browser_history, gecko`）+ 深化 2 个既有源（`state_db`, `claude_jsonl`）+ 一批 L4 查询 + L3 warehouse 列扩展。本 plan 由三份分层只读审计综合，经 **codex 三轮独立核对**修订至 v4。历轮吸收：基线失败真因（golden fixture 漏 patch `fetch_combined_pr_trends`，非措辞）、T0 的 live 副本还漏 github_pr、T4 异常契约定案、T5/T6 去重 README 认领、T10/T9 的 monkeypatch-seam 陷阱（`app.py` 的 `fetch_ado_pr_trends` F401 不能删）、T12 层级措辞、文件长度存量豁免。


## Goal

把快速迭代留下的**技术债还清、文档拉回自洽**。**范围严格限定为「清理与整理」**：修真 bug、消重复、补文档、修复采集漏配。**明确不做**：L5 digest 呈现新源（用户已多次明示暂缓）——作为"待办清单"记录在文末，不执行。

## 全局约束

- **不加功能、不加 L5 呈现**。纯清理。
- **行为等价**：重构（抽共享模块）后，adapter 对外行为须等价，靠现有测试 + 新增等价性测试兜底。若某处 codex 指出"非逐字节等价"（如 multica helper 的 stderr 截断长度、错误文本），需**显式决定**是否统一，并在 commit message 说明——不得默默改变可观察行为。
- **层边界（ADR-11）**：L1 不能 import L5。共享工具放**顶层**（peer of config.py）。
- **degrade-safe（ADR-23）**：所有 adapter 保持"源缺失/CLI 缺失/查询失败 → 返回 0 不抛"。
- **CST 口径**：时间分桶用显式 `+8h`，禁止 `localtime`（此纪律出自 **ADR-22**，非 ADR-2）。
- **不静默改外部 live 状态**：定时 runner（`scripts/aidata_digest_run.sh`）是提交进 repo 的脚本，但**实际 live 副本可能在别处**（如 `~/.hermes/cron/`）——plan 改 repo 内脚本，并**列出人工同步 live 副本的步骤**，不代为改动外部状态。
- **Style**：PEP 8、类型注解、函数 < 50 行、immutable。**文件 < 400 行仅适用于本 plan 新建的文件**（timeutil.py / _multica.py / 新测试）；**存量文件豁免**——尤其 `aidash.py`（927 行）已超标，T9 只做"改 import 来源"的最小改动，**不要求也不顺手把它拆到 400 行以下**（拆分是独立重构，不在本清理范围）。
